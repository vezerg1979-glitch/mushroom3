# Локальная сборка релиза

Пошагово: от чистой системы до подписанного APK, готового к загрузке
в RuStore. Всё то же самое умеет делать GitHub Actions
(`.github/workflows/build-release.yml`) — эта инструкция для случая, когда
собирать хочется у себя: когда нет интернета для CI, когда нужно быстро
проверить правку или когда ключ подписи не хочется отдавать никуда вовсе.

Отладочная сборка (`buildozer android debug`) отличается от релизной ровно
двумя вещами: ключом, которым подписан APK, и профилем `store`
в `buildozer.spec`. Всё остальное — тот же код.

---

## Шаг 0. Что должно быть в системе

Buildozer работает только под Linux или macOS. На Windows — через WSL2
(Ubuntu из магазина приложений), в чистой Windows он не соберётся.

```bash
sudo apt update && sudo apt install -y \
    git zip unzip openjdk-17-jdk python3-pip python3-venv \
    autoconf libtool pkg-config zlib1g-dev libncurses-dev libtinfo6 \
    cmake libffi-dev libssl-dev build-essential ccache
pip install --user buildozer cython==0.29.36
```

Версия Cython зафиксирована не из осторожности: на более новых
python-for-android 2024.01.21 не собирается.

Проверка, что java на месте:

```bash
java -version        # должно быть 17.x
buildozer --version
```

## Шаг 1. Ключ подписи — один раз на всю жизнь приложения

```bash
cd ~                 # НЕ в каталог проекта: в git ключу не место
keytool -genkey -v -keystore mushroom-release.keystore \
  -alias mushroom -keyalg RSA -keysize 4096 -validity 10000
```

Спросит пароль хранилища, потом имя, организацию, город, страну — отвечать
можно любое осмысленное, в карточке магазина это не показывается. В конце
спросит пароль ключа: проще сделать его таким же, как у хранилища, нажав
Enter.

Срок 10000 дней взят не случайно: магазины требуют ключ, действительный
минимум до 2033 года.

**Этот файл и пароль — самое ценное в проекте.** Потеряете — обновить
приложение в магазине будет нельзя никогда: только публиковать заново под
другим именем пакета, а у всех установивших останется старая версия без
обновлений. Скопируйте `mushroom-release.keystore` на флешку и запишите
пароль там же, где храните остальные важные пароли.

Проверить, что ключ читается и alias именно `mushroom`:

```bash
keytool -list -v -keystore ~/mushroom-release.keystore | head -20
```

## Шаг 2. Поднять номер версии

Магазин отвергает сборку, у которой код версии тот же или меньше уже
загруженного. Открыть `android/buildozer.spec` и поднять оба поля:

```ini
version = 2.9
android.numeric_version = 20900
```

Схема простая: 2.9 → 20900, 2.9.1 → 20901, 3.0 → 30000. `version` видит
человек, `numeric_version` — магазин.

Если 2.9 в RuStore ещё не загружалась, менять ничего не нужно.

## Шаг 3. Прогнать тесты

```bash
cd путь/к/проекту
python3 -m pytest -q
```

Должно быть зелено. Тесты дешёвые (секунды), а ловят они ровно то, что
после сборки заметить трудно: опечатку в номере счёта, разъехавшиеся QR
и ссылку, нечитаемый контраст, потерянный метод обработчика координат.
Подписанный APK со сломанной моделью никому не нужен.

## Шаг 4. Собрать

```bash
cd android

export P4A_RELEASE_KEYSTORE=$HOME/mushroom-release.keystore
export P4A_RELEASE_KEYSTORE_PASSWD='ваш-пароль-хранилища'
export P4A_RELEASE_KEYALIAS=mushroom
export P4A_RELEASE_KEYALIAS_PASSWD='ваш-пароль-ключа'

buildozer --profile store android release
```

Про эти команды стоит знать три вещи.

**Путь к ключу должен быть полным.** `~/mushroom-release.keystore` в кавычках
не раскроется, а `./ключ` буду искать относительно каталога, в который
buildozer перейдёт сам. `$HOME/...` или абсолютный путь — надёжно.

**Кавычки вокруг паролей одинарные.** В пароле легко оказывается `$`, `!`
или пробел; в двойных кавычках оболочка их истолкует по-своему, и подпись
провалится с невнятной ошибкой про неверный пароль.

**`export` живёт только в текущем окне терминала.** Закрыли — переменных
нет. Это не недостаток: пароль не остаётся в системе. Если собираете часто,
положите четыре строки в отдельный файл `~/.mushroom-release.env` с правами
`chmod 600` и подключайте его командой `source ~/.mushroom-release.env`
перед сборкой. В каталог проекта такой файл класть нельзя.

Первая сборка идёт 30–60 минут: качается Android SDK и NDK, компилируется
CPython под ARM. Последующие — минут пять-десять.

## Шаг 5. Проверить, что получилось

```bash
ls -lh bin/*.apk
```

Файл должен быть без слова `debug` в имени и весить порядка 25–40 МБ.

Проверить подпись:

```bash
APKSIGNER=$(find ~/.buildozer -name apksigner -type f | head -1)
"$APKSIGNER" verify --print-certs bin/*.apk
```

В выводе должно быть ваше имя из шага 1 и `Signer #1 certificate DN`.
Если там `CN=Android Debug` — сборка ушла с отладочным ключом: значит
переменные `P4A_RELEASE_*` не подхватились. Самая частая причина — их
задали в одном окне терминала, а `buildozer` запустили в другом.

## Шаг 6. Поставить на телефон и посмотреть

```bash
adb install -r bin/*.apk
```

**Отладочную сборку сначала удалите.** Подписи у debug и release разные,
Android откажется ставить одну поверх другой с ошибкой
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`. Удаление уносит с собой треки, снимки
и журнал — если там есть что жалко, выгрузите походы в GPX заранее
(журнал → поход → «Выгрузить GPX»), файлы лежат в каталоге приложения.

Что стоит проверить на релизной сборке отдельно от отладочной:

* прогноз считается (значит, сеть и разбор ответа Open-Meteo живы);
* поход пишет трек — строка под счётчиками должна показывать растущее
  «точек N»;
* карта показывает стрелку, а не точку, когда вы идёте;
* окно доната открывается и кнопка «Оплатить через Озон Банк» ведёт в банк.

## Если сборка упала

Buildozer многословен, и настоящая причина обычно тонет в выводе. Полезное
находится так:

```bash
buildozer --profile store android release 2>&1 | tee release.log
grep -n -i -E "error:|Command failed|What went wrong|Traceback" release.log | tail -20
```

Частые случаи:

| Что в логе | Что делать |
|---|---|
| `Aidl not found` | `buildozer android update`, затем повторить |
| `keystore was tampered with, or password was incorrect` | пароль не совпал: проверьте кавычки и раскладку |
| `SDK license not accepted` | `yes \| ~/.buildozer/android/platform/android-sdk/tools/bin/sdkmanager --licenses` |
| `Cython ... error` | не та версия: `pip install cython==0.29.36` |
| сборка встала на скачивании | `rm -rf ~/.buildozer/android/packages/...` и заново |

Совсем начисто:

```bash
buildozer android clean          # только сборочный каталог проекта
rm -rf ~/.buildozer              # и весь кэш SDK/NDK — следующая сборка час
```

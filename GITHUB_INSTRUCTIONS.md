# Загрузка проекта на GitHub и получение APK

## Способ 1. Через GitHub Desktop (без командной строки)

1. Распакуйте ZIP: внутри находится папка `Gortenziya_Moy_Sad_GitHub`.
2. В GitHub Desktop выберите **File → Add local repository → Choose…** и укажите распакованную папку.
3. Если программа предлагает создать репозиторий, согласитесь (**create a repository here**).
4. Сделайте первый коммит (Summary: `Initial Android app`) и нажмите **Publish repository**.
5. Откройте репозиторий на GitHub, перейдите в **Actions → Android APK → Run workflow**. На первое открытие GitHub может потребовать разрешить Actions для репозитория.
6. После завершения задания откройте его запуск и раздел **Artifacts**, скачайте `Gortenziya-Moy-Sad-debug-APK`.
7. Распакуйте скачанный архив: внутри `app-debug.apk`, который можно установить на Android-устройство в рамках стандартных настроек устройства.

При загрузке через веб-интерфейс GitHub нужно добавить **распакованные файлы с сохранением папок**, а не ZIP целиком. Файл `.github/workflows/build-android.yml` должен попасть в репозиторий: именно он запускает сборку.

## Способ 2. Через Git (Windows PowerShell или терминал)

Создайте **пустой** репозиторий на GitHub (без README и .gitignore), затем из распакованной папки выполните:

```bash
git init -b main
git add .
git commit -m "Initial Android app"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Замените `USERNAME/REPOSITORY` адресом **своего** репозитория. Для отправки понадобится авторизация GitHub. После отправки workflow автоматически запустится; его можно также запустить вручную в Actions.

## Где найти APK

`GitHub → ваш репозиторий → Actions → Android APK → успешный запуск → Artifacts → Gortenziya-Moy-Sad-debug-APK`.

`app-debug.apk` — тестовая (debug) сборка, подписанная стандартным отладочным ключом GitHub Actions. Она подходит для проверки на устройстве. Для публикации в Google Play понадобится отдельная релизная сборка с **вашим** ключом подписи; не храните ключи или пароли в репозитории.

## Что делать, если сборка не прошла

Откройте соответствующий запуск в Actions → `Test and build debug APK` и разверните красный шаг. Частые причины: недоступность сервисов загрузки Gradle/Android SDK, ограничения GitHub Actions для репозитория или реальная ошибка компиляции. Репозиторий содержит исходники и сценарий CI; до первой успешной сборки на GitHub наличие готового APK не гарантируется.

## Если Actions выдаёт `Failed to find package 'tools'`

В предыдущей версии workflow действие `android-actions/setup-android@v3` пыталось установить устаревший SDK-пакет `tools`. Его больше нет в репозитории Android SDK. В обновлённом проекте в `.github/workflows/build-android.yml` применяется `android-actions/setup-android@v4` с явным `packages: 'platform-tools'`.

Если проект уже загружен в GitHub, **не загружайте ZIP поверх репозитория**: откройте `.github/workflows/build-android.yml`, нажмите Edit (карандаш), замените старое содержимое на файл из нового архива, затем нажмите Commit changes. Перейдите Actions → Android APK → Run workflow. По завершении проверьте раздел Artifacts.

Если этот же запуск завершится другой ошибкой, откройте первый красный шаг и сохраните его журнал: проблема с отсутствующим пакетом `tools` устранена, но дальнейшая сборка может выявить независимую ошибку.

## Обновление до версии 1.1: фотографии и общий альбом

Этот документ был подготовлен для первоначальной версии. Чтобы загрузить обновление, замените в репозитории соответствующие файлы новым содержимым ZIP-проекта (в том числе `.github/workflows/build-android.yml`, `app`, `README.md` и `supabase`). Для личных фото дополнительных настроек не требуется. Для общего альбома — инструкция [`supabase/SETUP.md`](supabase/SETUP.md). После настройки добавьте GitHub Actions secrets `SUPABASE_URL` и `SUPABASE_ANON_KEY`, затем выполните новую сборку APK. Общий альбом **не подключается сам**, исходный архив не содержит учётных данных проекта. Без облачных настроек приложение остаётся офлайн-дневником с личными фотографиями.

## Обновление до версии 1.2: свои сорта

Загрузите новые исходные файлы поверх одноимённых в репозитории, **сохранив** `supabase.properties` вне репозитория и настройки GitHub Secrets. В приложении откройте «Справочник → Сорта → + Добавить новый сорт». Уже сохранённые кусты и фотографии не удаляются при обновлении приложения с тем же `applicationId` и совместимой подписью APK; JSON-копия сохраняет пользовательский каталог сортов. Личные сорта не публикуются в общем альбоме автоматически. Для обновления ранее установленного debug APK может потребоваться совпадение ключа подписи сборки; иначе Android предложит сначала удалить прежнюю версию — перед этим экспортируйте JSON и сохраните оригиналы фотографий (их байты в JSON не входят).


## Обновление до версии 1.3: фотодневник и поиск

Замените в существующем GitHub-репозитории файлы из нового ZIP **с сохранением структуры каталогов**, затем запустите Actions → Android APK → Run workflow. Метаданные фотографий (дата, этап роста и заметка) добавлены в существующий формат JSON; старые фото остаются в карточках с пометкой «Дата не указана». На новом телефоне JSON не восстановит сами JPEG-файлы: сохраните оригиналы отдельно. Функция «До / после» сравнивает только два фото одной гортензии. Общий альбом требует отдельно настроенного Supabase и модератора, а личные подписи и дата фото автоматически в сеть не отправляются.

## Версия 1.5 — сохранённые сравнения и календарь цветения

Загрузите содержимое ZIP в корень репозитория, сохраняя скрытую папку `.github`. Запустите workflow Android APK в Actions. Для обновления ранее установленного приложения требуется APK, подписанный тем же ключом. Сохраняйте локальные фотографии: JSON-резервная копия переносит метаданные и ссылки на фотографии, но не сами файлы изображений.

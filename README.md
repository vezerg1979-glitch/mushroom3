# Навигатор грибника

Прогноз плодоношения грибов по погоде: консольная утилита, десктопное приложение
на PySide6 и мобильное на Kivy с готовой сборкой APK.

├── main.py                    ЗАПУСКАТЬ ЭТО: сам выберет лучший интерфейс
├── desktop/
│   ├── mushroom_forecast.py   расчётное ядро + CLI
│   ├── mushroom_gui.py        интерфейс PySide6
│   ├── map_picker.py          выбор точки на карте OpenStreetMap
│   ├── places.py              сохранённые места и офлайн-кэш

## Быстрый старт

```bash
pip install PySide6
python main.py
```

`main.py` в корне сам решает, что запустить: есть PySide6 — полноценное окно,
есть только Kivy — мобильный интерфейс, нет ни того ни другого — консольный вывод.
Принудительно:

```bash
python main.py --ui desktop
python main.py --ui mobile
python main.py --ui cli --place "Фрязино" --days 10
```

При первом запуске открывается карта: щёлкните по нужному месту, найдите
населённый пункт поиском или впишите координаты. Выбор запоминается, потом
диалог вызывается кнопкой «На карте…». Тайлы OpenStreetMap кэшируются на диск;
без сети карта работает как координатная сетка — щелчок всё равно даёт координаты.
В мобильной версии место выбирается так же: кнопка с названием места вверху
экрана открывает карту с поиском по названию и списком сохранённых мест,
касание ставит метку. Кнопка **GPS** берёт координаты со спутника.
Тайлы там рисуются штатными средствами Kivy без сторонних пакетов:
`kivy_garden.mapview` тянет `requests` и свой рецепт сборки, а здесь всё
укладывается в математику Web Mercator и `UrlRequest`.

Место можно задавать и вручную — названием или парой координат: `55.9606, 38.0456`.
Мелкие сёла геокодер иногда знает только латиницей — программа сама пробует
транслитерацию, но координаты всегда надёжнее.

APK: залить каталог в репозиторий GitHub → Actions → **build-apk** → Run workflow →
скачать артефакт `mushroom-apk`. Подробности и локальная сборка — в `android/README.md`.

## Проверка на прошлых сезонах

```bash
cd desktop
python backtest.py --lat 55.9606 --lon 38.0456 --from 2015 --to 2025 --open
```

Считает индекс за каждый день выбранных сезонов по архиву Open-Meteo (ERA5, с 1940 года)
и строит HTML-отчёт: календарная карта «год × дата» плюс таблица — сколько было
грибных дней, когда первая волна, когда пик. Ответы архива кэшируются в
`~/.mushroom-backtest-cache`, повторные прогоны мгновенные.

Смысл: сравнить годы, которые вы помните грибными и пустыми, со столбцом «Дней ≥50».
Совпадает порядок — модель ловит межгодовую изменчивость, можно калибровать константы.
Не совпадает — сначала искать, какой сомножитель врёт.

## Разброс сценариев

Детерминированный прогноз на две недели — одна реализация из многих возможных,
и единственная линия индекса выглядит увереннее, чем она есть. Галочка
**«Разброс сценариев»** под графиком подтягивает ансамбль Open-Meteo
(ICON с откатом на GFS), считает индекс по каждому из трёх-четырёх десятков
сценариев и рисует коридор P10–P90 с медианой.

```bash
python mushroom_forecast.py --place "Фрязино" --days 14 --ensemble
```

Внизу выводится оценка горизонта: «сценарии согласованы примерно на 8 суток
вперёд, дальше разброс большой». Ближние дни у всех сценариев совпадают —
индекс там определяется уже выпавшим дождём. То есть грибной прогноз
предсказуем дальше, чем сама погода: лаг вида работает как память системы.

У членов ансамбля нет почвенных полей, поэтому влага для них считается
резервным способом. Коридор показывает разброс погодных сценариев,
а не полную неопределённость модели.

## Поход по лесу

Кнопка **«В лес»** на главном экране мобильной версии открывает режим записи:
сверху счётчики (метры, время в пути, число находок), в середине карта
с траекторией, снизу две крупные кнопки — «Старт» и «Нашёл!».

Сверху четыре счётчика: метры, время в пути, находки и время до заката.
Последнее — второе по важности число после расстояния до машины: темнеет
незаметно, под пологом ельника сумерки начинаются за полчаса до заката, а
грибник в это время как раз входит во вкус. Считается арифметикой по
координатам и дате (`sun.py`), без сети и разрешений, и за 45 минут до заката
предупреждает один раз. Так же один раз на порог предупреждает `power.py` при
падении заряда ниже 15 и 5 процентов: севший телефон — это не только
потерянный трек, но и потерянная дорога к машине.

Нажатие «Нашёл!» ставит красную метку в текущей точке и спрашивает вид; рядом
стоит кнопка отмены — ошибаются именно этой парой, промахнувшись видом или
нажав дважды. Постановка и отмена метки отзываются короткой вибрацией: метку
ставят не глядя на экран, руки заняты ножом и корзиной. Масштаб карты меняется
не только щипком, но и кнопками поверх неё — в перчатке и одной рукой щипок
не выходит. Кнопка «Весь поход» вписывает маршрут в экран целиком — ответ на
вопрос «где я относительно машины» без прокрутки карты пальцем; слежение при
этом выключается, иначе первая же координата вернула бы карту обратно.

Если по дороге между делянками человек проехал на машине, маршрут в этом
месте разрывается, а не склеивается прямой: проеханные километры не идут в
пройденное расстояние и не попадают в журнал, по которому калибруется модель.
Точка на время поездки одна и переезжает следом за машиной, поэтому к концу
она стоит там, где вышли. Одиночный скачок приёмника при этом по-прежнему
просто отбрасывается — разрыв делается только после серии быстрых точек
подряд (`track.FAST_BREAK`).

### Ночная тема

По грибы выезжают затемно, и белый экран в темноте бьёт по глазам: привыкание
к темноте сгорает за секунду, а под пологом леса после этого не видно ничего.
Кнопка в верхнем ряду переключает три состояния по кругу: авто, день, ночь.
«Авто» смотрит на солнце в той точке, для которой считается прогноз, — тёмная
тема нужна не в определённые часы, а когда темно, и в июне под Питером это
одно время, в ноябре под Ростовом другое. Подпись показывает и выбор, и что из
него вышло («Авто · ночь»), иначе непонятно, почему экран тёмный.

Ночной набор — не инверсия дневного. Фон тёплый тёмно-зелёный, а не чёрный:
чистый чёрный на OLED даёт резкую границу с любым светлым пятном, и глаз
дёргается на каждой кнопке. Плашки шкалы индекса тёмные и различаются
насыщенностью, а не яркостью: светлые дневные превратились бы в семь
фонариков. Кривые видов осветлены — коричневые на почти чёрном сливаются в
одну линию. Карта затемняется полупрозрачной пеленой, а маршрут и метки
остаются яркими: пелена лежит под ними, ради них карту и открывают.

Все цвета подобраны расчётом контраста, и тесты гоняют пороги по обеим темам.
Тёмная тема, набранная на глаз, проваливает их чаще светлой: на чёрном фоне
серый текст кажется читаемым, пока не выйдешь с телефоном на солнце.

Смена темы пересобирает экран, а не перекрашивает его: у виджета цвет
выставлен в момент создания, и задним числом палитра его не изменит. Данные
при этом остаются — прогноз не пересчитывается, в сеть приложение не лезет.
Уже открытые окна поверх экрана сохраняют прежние цвета до закрытия.

### Где машина

Стрелка возврата раньше вела к первой точке маршрута. Это машина ровно в
одном случае — если человек нажал «Старт» у багажника; жмут же его дома, на
шоссе и уже на просеке, и стрелка честно вела туда. При этом «где машина» и
есть главный вопрос, ради которого экран похода открывают в сумерках.

Теперь у похода есть отдельная точка машины, и приложение старается
поставить её само. При старте — на текущее место, потому что старт у машины
самый частый случай. Если после этого человек поехал, отметка едет вместе с
ним: это та же точка разрыва маршрута (см. `track.FAST_BREAK`), которая
сдвигается следом за машиной. А в момент, когда пошли пешком, отметка
переносится на первый пеший шаг — сама точка разрыва обновляется раз в
несколько координат и отстаёт от места остановки на сотни метров, а на такое
расстояние в сумерках по стрелке уже не выйдешь.

Кнопка «Машина здесь» остаётся для случаев, которые не угадать: машину
оставили за шлагбаумом и дошли пешком, приехали с товарищем, вышли из
автобуса. На карте отметка показана кружком с перекрестием — чтобы её нельзя
было спутать с началом маршрута: к одной из этих двух точек человек пойдёт
в темноте.

### Живучесть фоновой записи

Приложение поднимает сервис переднего плана с постоянным уведомлением — по
правилам Android этого достаточно, чтобы писать трек с погашенным экраном.
На Xiaomi, Huawei, Oppo, Vivo, Realme, Samsung и части других этого НЕ
достаточно: поверх системного механизма стоит собственный «оптимизатор»
производителя, который через десять-сорок минут убивает всё, чего нет в его
белом списке. Приложение при этом ничего не нарушает и никакой ошибки не
получает — его просто больше нет, а человек видит трек из первых двадцати
минут и делает единственный доступный вывод: программа сломана.

Поэтому `survival.py` делает три разные вещи. **Замечает**: разрывы во
времени между точками видны в самом маршруте, и после похода про них
говорится прямо. **Объясняет**: путь в настройках у каждого производителя
свой, и словами «разрешите работу в фоне» он не описывается, поэтому текст
подбирается по `Build.MANUFACTURER` — с названиями пунктов, как они
называются в MIUI, EMUI, ColorOS, One UI. **Доводит**: кнопки открывают
нужный экран настроек, потому что найти «Автозапуск» в MIUI по описанию
почти невозможно.

Перерывы, которые человек сделал сам кнопкой «Пауза», теперь записываются в
поход и из разрывов исключаются: обед на пне выглядит в точности как убитый
сервис, а ложное обвинение дороже пропущенного — человек пойдёт крутить
настройки, которые ни при чём. По той же причине вывод «виноват телефон»
делается осторожно: только при разрыве от четверти часа в походе длиннее
получаса, иначе разрыв списывается на потерянные спутники.

Разрешения `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` в сборке намеренно нет:
Google Play принимает его лишь для узкого списка назначений и снимает
приложения с публикации за неоправданное использование. Вместо системного
окна «разрешить работу в фоне?» открывается системный список оптимизации
батареи — на одно касание больше, зато сборку нельзя снять с публикации.

### Подсказка у старого места

Грибница живёт годами и плодоносит на том же месте — человек это знает и
ради этого ведёт журнал. Но в лесу он смотрит под ноги, а на карту глядит,
когда заблудился, и проходит мимо собственной прошлогодней точки в двадцати
метрах, не вспомнив о ней.

Поэтому телефон не показывает, а трогает: подойдя к старому месту находок,
он коротко дёргается в кармане, а под картой появляется строка вроде
«20 м: здесь брали белый гриб, 7 шт, в прошлом сезоне». Ничего не
открывается и экран не включается — человек сам решает, доставать телефон
или нет.

В `proximity.py` правил молчания больше, чем правил срабатывания, и это не
случайно: подсказка, дёргающая телефон не вовремя, раздражает сильнее, чем
радует, и её выключат вместе с полезной. Одно место срабатывает раз за
поход (человек ходит вокруг куста, то входя в круг, то выходя); между
любыми двумя сработками пауза в три минуты (места находок кучные); первые
две минуты похода — тишина (машину ставят там же, где в прошлый раз, а
находки бывают у самой опушки); при точности хуже 25 м подсказка молчит,
потому что «в двадцати метрах» тогда выдумка; единственная находка,
взятая однажды, местом не считается.

Текст намеренно без побуждений: «поищите вокруг» превращает подсказку в
указание, а человек и так знает, зачем он сюда пришёл. Выключатель —
в окне «Приём и сервис» на экране похода.

### Мелочи, которых не видно, пока их нет

**Выгрузка трека.** Кнопка «Выгрузить» в карточке похода кладёт GPX в общие
«Загрузки» и открывает выбор, куда его отправить: в мессенджер другу, в
облако, в OsmAnd. Раньше файл писался во внутренний каталог приложения, и
сообщался путь, по которому его нельзя достать ничем: кнопка формально
работала, а по сути нет.

**Последний вид первым.** В окне «Что нашли?» вид предыдущей метки
поднимается наверх списка. Грибы растут семьями: нашёл белый — через десять
шагов ещё белый, и прокручивать до него каждый раз мокрым пальцем в
перчатке незачем.

**Миниатюра в списке походов.** Первый снимок похода стоит слева от строки:
список листают глазами, и кадр узнаётся быстрее, чем читается название места.
Картинка лежит ПОВЕРХ кнопки, а не рядом с ней — соседний виджет съел бы
полсотни точек, на которых нажатие не работает, а строка должна нажиматься
целиком. Если файл снимка удалили из галереи, миниатюры просто нет: пустой
чёрный прямоугольник читается как поломка.

**Итог сезона.** «2026 год: походов 12, 47 км, находок 96. Чаще всего — белый
гриб (54). Лучший день — 14 сентября, Ельник у Гряды: находок 18». Показывается
только тем, у кого есть походы прошлых лет: в первый сезон эта строка слово в
слово повторяла бы общую сводку выше.

**Координаты метки.** Кнопка в карточке находки кладёт точку в буфер обмена
в виде «55.960600, 38.045600» — скучный формат намеренно: его понимают и
Яндекс, и Google, и OsmAnd, и человек на том конце просто вставляет строку в
поиск. «Стой там, я тебе точку скину» — обычный разговор в лесу, а передать
точку до сих пор было нечем.

### Как проверяется код, который живёт только на телефоне

Обёртки вокруг Android на сборочной машине не исполняются: jnius там нет,
все функции честно возвращают False, и тесты проходят мимо. Дважды подряд
это кончилось трассировкой в руках у человека — сначала правка затёрла
заголовок соседней функции, потом `cast` получил питоновскую строку вместо
Java-объекта. Обе поломки в две строки, обе невидимы для восьмисот тестов.

Поэтому таких проверок теперь две. `tests/test_module_api.py` читает код, не
исполняя его: находит обращения вида `модуль.имя` и вызовы с аргументами и
сверяет их с тем, что в модулях объявлено. `tests/androidfake.py` —
поддельные jnius и android, повторяющие не поведение системы, а её
строгость: `cast` так же отказывается принимать питоновскую строку, а
Java-строки возвращаются обычными `str`, как это делает настоящий pyjnius.
Через них прогоняются отправка копии, уведомления и открытие настроек.

Чего эти проверки не дают: примет ли система такой Intent, найдётся ли
программа для «Поделиться», хватит ли разрешений, не убьёт ли процесс
производитель. Это по-прежнему только живой телефон.

### Резервная копия

Журнал, походы, места и снимки лежат только на телефоне и больше нигде.
Потерянный телефон уносит с собой годы наблюдений, причём чем дальше, тем
дороже: на пятый сезон журнал стоит больше самого аппарата. Кнопка
«Резервная копия» в журнале походов собирает всё это в один zip.

Копий две. Без снимков — килобайты, проходит по почте. Со снимками — сотни
мегабайт, для носителя или облака; предупреждение о почтовом пределе в 25 МБ
показывается ДО сборки, а не после. В архив не кладётся то, что
восстановится само: кэш погоды и карты, служебный лог, незаконченный трек.

**Приложение не отправляет письма само, и это намеренно.** Для прямой
отправки нужен либо пароль от почтового ящика человека на телефоне (Gmail и
Яндекс такие входы закрыли, да и хранить чужой пароль — плохая мысль), либо
свой сервер-ретранслятор, через который пошли бы чужие координаты грибных
мест. Вместо этого архив кладётся в общие «Загрузки» и передаётся системе:
открывается обычное окно «Поделиться», где человек выбирает почту, облако
или мессенджер. Письмо уходит из его собственной программы и с его адреса.
Кнопка поэтому называется честно, а не «Отправить на почту» — тест за этим
следит: решив, что копия ушла сама, человек перестанет о ней думать.

Ссылка на файл берётся через MediaStore, потому что FileProvider в сборке
нет, а `Uri.fromFile` с Android 7 бросает `FileUriExposedException` (та же
история, что со снимками в `photos.py`). На Android 9 и старше content-ссылки
не получить — там копия просто сохраняется в «Загрузки», о чём и сообщается.

Восстановление ничего не затирает: файлы, которые уже есть на телефоне,
пропускаются, чтобы прошлогодняя копия не съела сегодняшний поход. Архив
проверяется до распаковки — по описи внутри, — и пути вида `../../`
отбрасываются: копия приходит из почты и с чужой флешки, то есть из места,
которому доверять нельзя.

### Прогноз и то, что вышло

При выходе в лес поход запоминает индекс, который модель обещала на этот
день по каждому виду. Записывается он в момент старта и больше не меняется —
пересчитать его потом нельзя по двум причинам: для пересчёта нужны архивная
погода и сеть, которых в лесу нет, а главное, пересчёт даст сегодняшнюю
версию модели с сегодняшними коэффициентами, тогда как вопрос стоит иначе —
что приложение обещало ТОГДА и чем это кончилось.

Карточка похода показывает обещание рядом с итогом, а список походов —
свою шкалу: с какого индекса выезды этого человека были удачными. Она нужна
потому, что у каждого леса шкала своя: где-то 45 означает полную корзину,
где-то и при 70 пусто, и общий прогноз этого знать не может. Считается шкала
нарочно грубо, границей между лучшим пустым и худшим удачным выездом, и
молчит, пока походов меньше шести: три точки — совпадение, а не
закономерность. Если границы в данных нет, так и написано, вместо
придуманного порога.

### Эталонные изображения

В окне «Что нашли?» у каждой строки слева стоит эталон вида, а по кнопке
«крупно» открывается карточка: рисунок во весь экран, признаки и двойники.
Одиннадцать одинаковых надписей в лесу читаются плохо — экран в бликах,
глаза заняты землёй, — а картинка узнаётся раньше, чем прочитано слово.
Нажатие ловит вся строка целиком: маленькая мишень рядом с большой означает
промах в перчатке. Тот же эталон с кнопкой «Сверить» есть в карточке метки,
рядом со своими снимками: сверять имеет смысл, пока гриб в руках, а не в
корзине вперемешку с остальными.

Если, сверившись, человек понял, что вид не тот, прямо в карточке эталона
есть кнопка «Это другой вид»: она открывает тот же список, и метка меняет вид,
сохраняя снимки, заметку и координаты. Раньше исправить ошибку можно было
только удалением метки — вместе со снимками, которые уже не переснять. По той
же причине строка вида есть и у метки, поставленной без вида: он часто
становится понятен позже, дома, по фотографии.

Изображения нарисованы линиями и заливками (`atlas.py`), а не сфотографированы.
Фотография в APK — это чужое авторское право и лишние мегабайты, а главное,
одна фотография всё равно не покрывает разброс внутри вида: белый бывает и
светлым колосовиком, и почти чёрным листопадником. Схематичный силуэт с
честным цветом на такое не претендует и не создаёт ложной уверенности: он
отвечает на вопрос «на какую кнопку жать», а не «съедобно ли это». Поэтому
определение вынесено в текст карточки — признаки, двойники и чем двойник себя
выдаёт: жёлчный гриб у белого, ложные опята и галерина у опёнка, бледная
поганка у сыроежки, гиромитрин у строчка.

Свои фотографии подставляются без правки кода: положите файл в
`android/assets/species/<slug>.jpg` (имена — в таблице `SLUG` того же модуля,
латиницей: кириллица в путях внутри APK на разных прошивках ведёт себя
по-разному) и пересоберите. Виджет покажет фотографию вместо рисунка.

Последнее выбранное место переживает закрытие приложения: человек, который
ездит в одну сторону, не должен каждый запуск начинать с чужого леса.
По окончании похода трек сохраняется в `tracks/` в двух видах: JSON для самой
программы и GPX, который открывается в OsmAnd, Garmin и любом навигаторе.
Находки автоматически ложатся в журнал наблюдений с баллом обилия по числу
найденных штук — то есть каждый поход делает калибровку модели точнее.

Про расстояние: сырой GPS-трек всегда длиннее реального пути, потому что точки
дрожат на месте. Поэтому отбрасываются точки с точностью хуже 50 м, шаги короче
6 м не засчитываются, а скачки быстрее 8 м/с считаются выбросом приёмника.
Без этих фильтров за час стояния у костра «набегает» лишний километр.

### Прошлые походы на карте

Карта похода показывает не только сегодняшний трек. Под ним блёклыми нитками
лежат маршруты прошлых выездов, а поверх — точки мест, где брали: цвет по виду
(тот же, что в легенде графика), размер по числу взятого. Смысл в том, что
грибник ходит по одним и тем же местам годами, а голова их теряет — особенно
через сезон. Приложение всё это время их записывало, но пока они лежали только
в журнале, толку в лесу не было: список записей на ходу не листают.

Касание по точке открывает карточку — что, сколько, когда и сколько раз здесь
брали. Кнопка **«Идти сюда»** ведёт к ней той же стрелкой, что и «К машине»,
а **«В мои места»** превращает грибной угол в место с именем и собственным
прогнозом: имя предлагается готовым («Белый гриб, 24.08.2025»), потому что
ввод текста мокрыми руками в лесу — гарантия, что место не сохранят вовсе.
Значок тетради на карте слой выключает: в исхоженном квадрате своих ниток за
пять сезонов столько, что сегодняшний трек в них теряется.

Подложка готовится в `history.py` и читается в фоновом потоке — окно похода
должно открываться мгновенно. Сырые треки прореживаются Дугласом-Пойкером
(допуск 12 м, потолок 300 точек на маршрут): рисовать тысячи точек на каждый
тик GPS карта не успевает, а на экране разницы нет. Находки ближе 30 м друг
к другу сливаются в одно место — иначе пять меток у одной ели дают кляксу
вместо ориентира. Тот же слой виден и на карте выбора места для прогноза.


Запись ведёт отдельный процесс Python — фоновый сервис Android с постоянным
уведомлением. Телефон можно убрать в карман и погасить экран, маршрут продолжит
писаться. Сервис объявлен в `buildozer.spec` строкой
`services = Tracker:service_tracker.py:foreground`.

Сервис и приложение общаются через файл: сервис дописывает точки построчно
в NDJSON, приложение дочитывает его с последней позиции. Способ выбран ради
устойчивости — переживает перезапуск любой из сторон, а сырой лог остаётся
на диске, так что убитое системой приложение не уносит с собой поход.

Координаты берутся через `LocationManager` напрямую (pyjnius), без plyer:
plyer ломал сборку и всё равно сводится к тому же вызову. Если сервис
не поднялся, приложение честно сообщает об этом и переходит на запись
при открытом экране; кнопка «Сервис» на экране похода показывает журнал
диагностики.

Цель сборки понижена до API 33: начиная с 34 Android требует объявлять тип
foreground-сервиса в манифесте, чего шаблон python-for-android не делает.

### Шрифт и значки

В шрифте, который Kivy кладёт в APK (Roboto из своей поставки), нет ни стрелок,
ни блочных знаков, ни карточных мастей — только латиница, кириллица и обычная
пунктуация. Любой символ вроде «♥», «≡», «→» или «▇» превращается на телефоне
в пустой квадрат, а на компьютере при отладке рисуется нормально: там
подставляется системный шрифт. Так уже трижды ловили сломанные с виду кнопки
и нечитаемые подсказки.

Поэтому значки рисуются геометрией (`icons.py`), направления в навигации
названы словами, полоски в объяснениях набраны длинными тире, а тест
`test_icons.py` разбирает строковые литералы всех модулей интерфейса и падает
на любом знаке, которого в шрифте нет. Список того, что в шрифте есть, получен
разбором самого файла Roboto-Regular.ttf из поставки Kivy.

## Мои места

Точку с именем и типом леса можно запомнить: «Запомнить» в десктопе, кнопка ★
в мобильной версии. У каждого места свой профиль почвы, поэтому прогноз
для сосняка и для низины считается по-разному.

Вкладка **«Куда ехать»** считает все сохранённые места разом и выводит таблицу
«место × день» с одной строкой вывода: где и когда будет лучше всего.

Последний удачный расчёт по каждому месту кладётся в кэш (`cache/` в каталоге
данных). Если сети нет, показывается он с пометкой о давности — в лесу это
единственный работающий вариант. Кэш старше четырёх суток не используется.

Каталог данных: `~/.mushroom-forecast`, переопределяется переменной
`MUSHROOM_DATA_DIR`; на Android — приватный каталог приложения.

## Тип леса

Профиль биотопа задаёт почвенные константы, затенение и пригодность для каждого вида:

| Профиль | θ завядания–ПВ, м³/м³ | Особенности |
|---|---|---|
| Смешанный лес | 0.10–0.36 | профиль по умолчанию, суглинок |
| Сосняк на песке | 0.05–0.21 | втрое меньше воды, быстро сохнет; маслёнок ×1.3, груздь ×0.4 |
| Березняк, суглинок | 0.11–0.37 | самый отзывчивый на дождь; подберёзовик ×1.3 |
| Ельник | 0.13–0.41 | густой полог, почва на 1.5 °C холоднее; слой сдвинут позже |
| Низина, пойма | 0.14–0.44 | влага держится долго; груздь ×1.25, белый ×0.75 |

Выбирается в списке «Лес» в десктопной версии, спиннером в мобильной,
ключом `--biotope` в консоли и в `backtest.py`. В журнале есть колонка «биотоп»,
и калибровка считает каждую запись со своим профилем.

## Журнал и калибровка

```bash
cd desktop
python journal.py init                 # создать journal.csv
python journal.py add --species белый --score 3 --place "Дальний бор"
python journal.py stats                # что накоплено
python calibrate.py --dry-run          # посчитать подгонку, не записывая
python calibrate.py                    # записать calibration.json
```

Журнал — обычный CSV с разделителем «;», открывается Excel двойным щелчком.
Одна строка — один вид в одном выезде, обилие по шкале 0–5. **Пустые выезды
(обилие 0) фиксируйте обязательно**: без них модель не научится говорить «не ехать».

`calibrate.py` поднимает архивную погоду на дату каждой записи и подбирает константы
симплексом Нелдера–Мида так, чтобы расчёт лёг на ваши оценки. Часть записей
откладывается в контрольную выборку: если на ней стало хуже — это переобучение,
и файл не пишется. Результат — `calibration.json` рядом с ядром, подхватывается
автоматически; текущий статус виден в сводке по погоде.

Ориентир по объёму: 30 записей — минимум для глобальных коэффициентов,
60+ — чтобы трогать параметры отдельных видов.

### Разметка в подписях

Kivy разбирает в подписях теги `[b]`, `[color=…]`, `[size=…]`. Почти всякая
посторонняя квадратная скобка проходит насквозь, но `[size=нечисло]`
разбирается всерьёз и роняет отрисовку. Опасен здесь не причудливо названный
лес, а окно аварии: в него уходит текст исключения, а он бывает каким угодно.
Окно, которое падает, показывая ошибку, не оставляет человеку ничего.

Поэтому всё, что пришло не от программиста — трассировка, название места,
заметка, ответ сервера, — проходит через `markup.esc()`. Свои теги при этом
пишутся вокруг уже экранированного текста.

### Дымовой прогон интерфейса

Все остальные тесты проверяют арифметику и разбирают исходники: это дёшево и
ловит многое, но не трогает сам Kivy. Из-за этого на телефон однажды уехала
кнопка, падавшая прямо в конструкторе экрана похода, — геометрия значка была
верной, а его отрисовка нет, и тесты были зелёными.

`tests/smoke_ui_test.py` создаёт окна по-настоящему и нажимает всё, что можно
нажать: старт похода, метку, отмену, вписывание маршрута, карточку старой
находки, разбор дня. Нужен экран, поэтому локально запускать так:

```bash
xvfb-run -a python -m pytest tests/smoke_ui_test.py -q
```

Имя файла не `test_...` намеренно: обычный прогон идёт через
`unittest discover`, а тот не умеет пропускать модуль целиком и без экрана
засчитал бы его как ошибку.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Сеть не используется: ответы API подменяются заглушками, погода
строится синтетически. Покрыто: поведение на характерных сценариях (засуха,
ливень с лагом, морось, жара, заморозок, осенняя волна опят), свойства расчёта
(границы шкалы, нормировка ядра, монотонность по осадкам), приоритет почвенных
данных над резервными формулами, перебор наборов слоёв, транслитерация
геокодера, калибровка и разбор журнала, проекция карты, подсчёт волн.

93 теста, в CI прогоняются на Python 3.10 и 3.12 при каждом коммите.

## Модель

1. **Влага почвы** — объёмная влажность слоя 0–7 см из погодной модели, переведённая
   в долю доступной влаги: (θ − θ_завядания) / (θ_ПВ − θ_завядания), 0.10 и 0.36 м³/м³.
   Резерв, если модель слой не отдаёт: резервуар подстилки 55 мм, приход = осадки × 0.85,
   расход = ET0 × 0.55 × β, где β = 0.3 + 0.7·(W/C) — сухая подстилка сохнет медленнее.
2. **Температура почвы** — слой 0–7 см из той же модели. Резерв: экспоненциальное
   сглаживание температуры воздуха (α = 0.32, лаг ~3 суток, поправка −1.2 °C под пологом).
   Фактический источник показывается в интерфейсе.
3. **Импульсный отклик** — закладка примордиев = f(влага) · f(T) · (0.3 + 0.7·импульс дождя):
   плодоношение это реакция на событие увлажнения, а не на стационарную сырость.
4. **Свёртка с лаговым ядром вида** — 3–16 суток («слой через 7–10 дней после дождя»).
5. **Поправки** — сезон по месяцам, гибель урожая от заморозка/жары/суши,
   для опят триггер осеннего похолодания с плавным затуханием, для весенних
   видов — накопленное тепло после схода снега.

### Весенние виды

Сморчок и строчок считаются не по календарю, а от схода снега. Дата схода
берётся по высоте снежного покрова (`snow_depth`), а при её отсутствии — по
первому устойчивому переходу температуры почвы через нуль. Дальше копится сумма
(T почвы − 5 °C) по суткам: строчку нужно около 85 °C·сут, сморчку около 155.

Из-за порога в +5 °C ранний сход снега в холодном марте слой не ускоряет —
тепло начинает накапливаться только с прогревом, и это соответствует
наблюдаемым срокам. Весной роль импульса играет талая вода, а не дождь,
поэтому доля фоновой закладки у этих видов выше (0.70 против 0.30).

Проверка на характерных сценариях: месячная сушь → 0; ливень 35 мм и 9 суток → 62
(«хорошо»); постоянная морось → 62; дожди при +30 °C → 2 (жара выключает белый);
осенняя волна опят даёт плавный пик через ~12 суток после похолодания.

Калибровочные константы `CAPACITY_MM`, `CANOPY`, `BASE`, `GAIN` и профили видов
(словарь `SPECIES`) — в начале `mushroom_forecast.py`. Модель эвристическая;
по журналу выездов её параметры можно подогнать по МНК.

## Данные

Карта — [OpenStreetMap](https://www.openstreetmap.org/copyright), лицензия ODbL,
тайлы через штатный сервер (личное использование, с кэшированием).

Погода — [Open-Meteo](https://open-meteo.com), лицензия CC-BY, без API-ключа:
31 сутки истории и до 16 суток прогноза. Геокодирование по названию места — тот же сервис.

## Навигация в лесу (2.7)

Экран «Поход» умеет вести обратно к машине: кнопка «К машине» разворачивает
стрелку с расстоянием. Пока человек идёт, подсказка относительная — «↘ вправо-назад,
1,0 км»; если остановился, показывается азимут — «на юго-запад».

Разделение по файлам сознательное: `nav.py` и `tiles.py` не знают ни про Kivy,
ни про Android и потому целиком проверяются тестами на компьютере, а
`navwidget.py` только рисует. Компас не используется: под пологом леса он врёт,
направление считается по хвосту трека.

`tiles.py` качает карту впрок в тот же кэш, что использует `mapview` — иначе
в лесу без сети подложка пустая.

## Тесты

```bash
pip install pytest && pytest -q
```

`tests/test_packaging.py` стережёт настройки сборки APK: заглушку `filetype.py`,
закреплённые версии p4a и NDK, объявление фонового сервиса. Каждая проверка
там — след реальной поломки, стоившей получаса сборки и отладки на телефоне.
